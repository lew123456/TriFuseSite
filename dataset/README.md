# Benchmark datasets

| Directory | Partitions |
|---|---|
| `PPI/` | Train334, Test60, Test315-28, Btest25, UBtest25 |
| `SMPI/` | Train1628, Valid348, Test348 |
| `DPI/` | Train458, Valid115, Test129 |
| `RPI/` | Train396, Valid99, Test117 |
| `splits/` | Protein IDs for each partition |
| `features/ppi/` | PSSM, HMM, DSSP and resAF NPY arrays |
| `metadata/` | Partition catalog, dataset statistics and structure URLs |

Each `.fa` file uses three lines per record: `>ID`, amino acid sequence,
and a binary label string of the same length (`1`: binding; `0`: non-binding).
The corresponding `.jsonl` stores these records with structure and feature
paths. Paths are relative to the manifest file. These three-line files should
be read with the supplied parser, rather than a standard sequence-only FASTA reader.

PPI and SMPI use fixed benchmark memberships. DPI-Train573 and RPI-Train495
are partitioned with NumPy `default_rng(2025)`: the first `round(0.2*N)`
permuted indices form the validation set; record order is preserved within
each split. The resulting ID lists are provided in `splits/`.

PPI-Btest25 is a subset of Test60. Its paired unbound chains are listed in
`PPI/paired_mapping.tsv` and `PPI/pairs.jsonl`. The reported residue-range field
is retained from the original mapping. Each conformation retains its own
benchmark sequence and labels.

The 2,824 PPI feature arrays cover 706 distinct chain IDs, with 20 PSSM, 20 HMM,
14 DSSP and 7 resAF columns per residue. Coordinates, PPI pseudopositions and
distance maps are supplied separately. ESM embeddings are generated by
`main_extract_esm.py`. Their input formats are described below.

```bash
python main_validate_datasets.py
python main_prepare_datasets.py --tasks ppi smpi dpi rpi --check-only
```

`metadata/dataset_statistics.csv` contains the protein, residue and positive-label
counts. `SHA256SUMS.json` provides checksums for the distributed files.

## Model input preparation

`main_prepare_datasets.py` creates `data/<task>/<split>/` from the benchmark
manifests. These generated paths match the task configuration files.

### Structures

Default coordinate locations are `dataset/structures/PDB/<pdb_id>.pdb` (or
`.cif`) and `dataset/structures/AlphaFoldDB_v6/<accession>.pdb`. Alternatively,
pass `--structure-index structures.jsonl`, containing one record per override:

```json
{"task":"ppi","id":"2c0lA","path":"coordinates/2c0l.pdb","chain":"A"}
```

Paths are relative to the index file. An unavailable structure is specified by
`path: null` and a `reason`. Otherwise missing files are reported by `--check-only`.
Sequence and label positions are retained under masking. The first model is used;
chain selection and exact-residue alignment determine the valid coordinates.
Experimental coordinates use observed-position confidence; AlphaFold coordinates
use pLDDT/100.

### PPI geometry

Supply the benchmark arrays using `--ppi-geometry-root` with the following layout:

```text
pseudopositions/<protein_id>.npy   # [L,3], Angstrom
distance_map/<protein_id>.npy      # [L,L], Angstrom
```

PPI features concatenate PSSM (20), HMM (20), DSSP (14), resAF (7), and
`norm(position_i-position_0)/15` (1). SMPI/DPI/RPI construct their 62-dimensional
descriptors from the sequence. ESM inputs have shape `[L,1280]`.

### Generated files

Each prepared partition contains `manifest.jsonl`, protein `.npz` files, and
generated `.esm.npy` embeddings. The NPZ stores features, labels, CA coordinates,
structural confidence/masks and graph arrays. A manifest entry is:

```json
{"id":"example","npz":"example.npz","esm":"example.esm.npy"}
```

`main_prepare.py` also accepts a custom raw JSONL with `id`, `sequence`,
`labels`, `structure_path`, `chain` and `structure_source`; PPI additionally
requires `ppi_features` paths for the four descriptor arrays and two geometry
arrays. Use `scripts/from_triplet_fasta.py` to convert three-line benchmark files.
